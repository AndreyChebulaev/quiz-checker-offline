# Эксперимент: выбор модели и порога

## Зачем
Приложение считает ответ верным, если косинусное сходство его эмбеддинга с одним из эталонных
ответов не меньше порога. Модель и порог раньше выбирались без измерений. Эксперимент
сравнивает несколько методов на размеченном наборе и подбирает порог.

## Данные — `data/answers_intelligent_systems.csv`
Дисциплина «Интеллектуальные системы и их проектирование»: **25 вопросов, 200 ответов**.
На каждый вопрос 8 ответов шести типов:

| Тип (`category`) | Сколько | Метка (`label`) | Что моделирует |
|---|---|---|---|
| `para` — верный, перефраз | 2 | 1 | правильный ответ своими словами |
| `short` — верный, кратко | 1 | 1 | правильный ответ ключевыми словами |
| `partial` — неполный | 1 | 0 | общие слова без сути |
| `wrong` — неверный по теме | 2 | 0 | ошибочный ответ с терминами дисциплины |
| `neg` — искажение смысла | 1 | 0 | верный ответ с перевёрнутым смыслом («не», «от цели к фактам» вместо «от фактов к цели») |
| `off` — не по теме | 1 | 0 | «не знаю» или посторонний текст |

**Ограничение:** ответы составлены вручную (синтетические), а не собраны у студентов, метки
проставлены по типу ответа. Это нужно указать в тексте работы. Метки стоит просмотреть
(открыть CSV в Excel, столбец `label`): спорные случаи можно исправить и перезапустить эксперимент.

`data/test_intelligent_systems.xlsx` — те же вопросы с эталонами в формате теста для приложения.

## Методы
- **Лексические (базовые):** коэффициент Жаккара по основам слов; TF-IDF по символьным 3–5-граммам.
- **Модели предложений:** multilingual MiniLM-L12 (используется в приложении), all-MiniLM-L6
  (англоязычная, использовалась в онлайн-версии), multilingual MPNet-base, LaBSE,
  multilingual-E5-small, ruBERT-tiny2.

## Как оценивается
- **ROC-AUC** — насколько хорошо оценка разделяет верные и неверные ответы независимо от порога.
- **F1 и Accuracy с кросс-валидацией:** вопросы делятся на 5 групп; порог подбирается по F1
  на 4 группах и проверяется на пятой. Так порог не «подгоняется» под те же данные, на которых измеряется качество.
- Доля засчитанных ответов **по каждому типу** — показывает, на чём метод ошибается.
- Скорость: миллисекунды на один текст.

## Запуск
Нужен интернет: при первом запуске скачается около 3 ГБ моделей в `local_models/`.
```bat
.venv\Scripts\activate
pip install -r requirements-dev.txt
python experiments\run_experiment.py
```
Без интернета: `python experiments\run_experiment.py --offline` (только уже скачанные модели).
Результаты: `experiments/results/<дата_время>/report.md` и графики рядом.

1. **Выбрана модель ruBERT-tiny2**, обученная на русском языке: лучшее качество по всем метрикам,
   самая быстрая (в 9–24 раза быстрее остальных) и самая компактная. Порог 0.71 устойчив: при
   кросс-валидации он одинаков во всех пяти разбиениях.
2. **Порог нужно подбирать под модель.** Прежний порог 0.76 для MiniLM-L12 давал F1 = 0.36
   (отклонялась большая часть верных ответов), а подобранный 0.60 дал F1 = 0.70.
3. **Англоязычная модель хуже даже простых лексических методов** (F1 0.61 против 0.65–0.68):
   переход на модель, обученную на русском, был оправдан.
4. **Модель понимает перефразирование:** 100 % верных ответов своими словами засчитаны, хотя
   лексических совпадений с эталоном в них мало. Короткие ответы ключевыми словами засчитаны в 68 %.
5. **Главное ограничение — искажение смысла.** Ответы с отрицанием или перевёрнутой логикой
   засчитываются в 84 % случаев: по словам они почти совпадают с эталоном. Это 21 из 31 ложного
   срабатывания. Ограничение общее для всех методов на основе сходства (52–92 %).
6. **Как это компенсировать** (этап 5): ответы, у которых число слов-отрицаний («не», «нет», «без»…)
   не совпадает с эталоном, отправлять на проверку преподавателю. На этом наборе это 12 % ответов;
   доля автоматически засчитанных искажённых ответов падает с 84 % до 24 %, а точность
   автоматических решений растёт с 0.80 до 0.86. Оценка предварительная: она получена на всём
   наборе без кросс-валидации.

**Ограничения эксперимента:** ответы синтетические, одна дисциплина, 200 ответов. Для
более надёжных выводов нужен набор реальных ответов студентов.

## Проверка правил ручной проверки (этап 5)

Те же оценки ruBERT-tiny2, порог 0.71, правила из `services/scoring.py`:

| Правила | На проверку | Точность автоматических решений | Ложные зачёты | Ложные незачёты | Искажения засчитаны автоматически |
|---|---|---|---|---|---|
| только порог | 0 % | 0.785 | 35 | 8 | 88 % |
| + серая зона 0.03 | 7 % | 0.785 | 35 | 5 | 88 % |
| + проверка отрицаний | 12 % | 0.857 | 17 | 8 | 24 % |
| **+ оба правила (по умолчанию)** | **20 %** | **0.863** | **17** | **5** | **24 %** |

- Проверка отрицаний вдвое сокращает ложные зачёты (35 → 17): почти все пойманные — искажения смысла.
- Серая зона сама по себе точность не повышает (в неё попадают и верные краткие, и неверные
  ответы), но возвращает преподавателю часть верных ответов, которые иначе были бы отклонены (8 → 5).
- Цена — 20 % ответов на ручную проверку. Ширину зоны можно уменьшить или выключить в настройках
  теста (поле «Ширина зоны ручной проверки», 0 — выключить).
- Ограничение: правило ловит только искажения через отрицание. Перестановка понятий без отрицания
  («от цели к фактам» вместо «от фактов к цели») остаётся незамеченной — для этого нужна модель
  логического следования (NLI), что выходит за рамки работы.
