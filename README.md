# Система автоматизированной проверки открытых вопросов

Веб-приложение для тестирования студентов с **открытыми ответами**: студент пишет ответ
своими словами, а система сравнивает его по смыслу с эталонными ответами преподавателя
с помощью модели машинного обучения. Спорные ответы не решаются автоматически, а
отправляются преподавателю на проверку.

Работает **полностью офлайн**: модель хранится на диске, интернет нужен только один раз
для её загрузки.

Выпускная квалификационная работа, ТИУ, группа РПСб-23-1.

## Возможности

**Студент**
- проходит доступные ему тесты с лимитом времени, числом попыток и дедлайном;
- видит решение по каждому ответу: «верно», «неверно» или «на проверке у преподавателя»;
- смотрит историю своих результатов.

**Преподаватель**
- создаёт тесты в редакторе или импортирует из Excel; у вопроса может быть несколько эталонов;
- задаёт ограничения, порог зачёта и ширину «зоны ручной проверки» для каждого теста;
- открывает тест всем студентам, выбранным студентам и группам или закрывает его от студентов;
- видит только свои тесты; может открыть коллегам доступ к тесту и (отдельно) к результатам;
- проверяет спорные ответы в разделе «Проверка» — итог студента пересчитывается сразу;
- выгружает результаты в Excel, ищет по ним обычными фразами: «процент больше 80 РПСб», «больше двух попыток».

**Администратор**
- управляет пользователями, выдаёт логины и пароли (в том числе списком из Excel/CSV);
- видит все тесты и результаты (переключатель «Мои / Все тесты»), передаёт тест другому преподавателю.

## Как проверяется ответ

1. Ответ студента и эталоны превращаются в векторы моделью **ruBERT-tiny2**
   (`cointegrated/rubert-tiny2`, 114 МБ, обучена на русском языке).
2. Оценка ответа — максимальное косинусное сходство с эталонами.
3. Решение (`services/scoring.py`):
   - оценка ≥ порога (по умолчанию **0.71**) — **верно**;
   - оценка в «серой зоне» [порог − 0.03; порог) — **на проверку**;
   - оценка ≥ порога, но число отрицаний («не», «нет», «без»…) не совпадает с эталоном —
     **на проверку**: возможно, смысл перевёрнут;
   - иначе — **неверно**.

Модель и порог выбраны экспериментом на размеченном наборе из 200 ответов: сравнивались
6 моделей и 2 лексических метода, порог подбирался кросс-валидацией по вопросам.
Подробности, таблицы и графики — в [`experiments/README.md`](experiments/README.md).

| | ROC-AUC | F1 (кросс-валидация) |
|---|---|---|
| ruBERT-tiny2 (выбрана) | 0.864 | 0.774 |
| multilingual MiniLM-L12 (была) | 0.790 | 0.703 |
| TF-IDF, без нейросети | 0.798 | 0.648 |

## Установка (Windows)

Нужен Python 3.13.

```bat
cd fastapi_quiz_app_local
py -3.13 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python download_model.py          :: один раз, нужен интернет (~120 МБ)
```

`download_model.py --all` дополнительно скачивает запасную модель MiniLM-L12.

## Запуск

```bat
.venv\Scripts\activate
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Сайт откроется по адресу http://localhost:8000, в локальной сети — по IP компьютера.

**Первый вход.** При первом запуске создаётся администратор `admin` со случайным паролем —
он записан в `first_admin_credentials.txt`. Смените пароль (меню профиля → «Сменить пароль»)
и удалите файл. Задать пароль заранее: `set QUIZ_ADMIN_PASSWORD=...` перед первым запуском.

## Демо-данные для показа

Отдельная демо-база с преподавателями, группой студентов, тестом по дисциплине
«Интеллектуальные системы и их проектирование» и уже пройденными попытками:

```bat
set QUIZ_DATABASE_PATH=demo.db
set QUIZ_UPLOAD_DIR=demo_files
python scripts\load_demo_data.py
python -m uvicorn main:app
```

Логины и пароли — в `demo_credentials.txt`. Студент `demo_st6` тест ещё не проходил:
на нём удобно показать прохождение вживую. Рабочая база (`users.db`) при этом не меняется.

## Настройки

Переменные окружения (все необязательны):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `QUIZ_DATABASE_PATH` | `users.db` | файл базы SQLite |
| `QUIZ_UPLOAD_DIR` | `uploaded_files` | папка с тестами |
| `QUIZ_MODEL` | `rubert-tiny2` | папка модели в `local_models/` |
| `QUIZ_AI_THRESHOLD` | порог модели (0.71) | общий порог зачёта |
| `QUIZ_REVIEW_MARGIN` | `0.03` | ширина «серой зоны» |
| `QUIZ_NEGATION_CHECK` | `1` | проверка отрицаний (`0` — выключить) |
| `QUIZ_SESSION_HOURS` | `12` | время жизни сессии |
| `QUIZ_ADMIN_PASSWORD` | — | пароль первого администратора |

Порог и зону проверки можно задать и для отдельного теста в редакторе.

## Безопасность

- пароли хранятся как PBKDF2-SHA256 с солью; выданные пароли показываются один раз;
- сессии хранятся в базе (в виде хеша токена), cookie `HttpOnly` и `SameSite=Lax`;
- ограничение перебора: 5 неудачных входов на логин за 5 минут;
- права проверяются на сервере для каждого действия; чужие тесты для преподавателя «не существуют».

## Структура проекта

```
main.py                 точка входа: сборка приложения
config.py               настройки
core/                   ядро: БД и миграции, пароли, сессии, общие функции веб-слоя
services/               бизнес-логика
  ai_backend.py           загрузка модели, вычисление сходства
  scoring.py              решение «верно / неверно / на проверку»
  quiz.py                 банк вопросов (кэш эмбеддингов) и состояние попытки
  review.py               оценки ответов и проверка преподавателем
  test_access.py          владельцы тестов и доступ преподавателей
  test_settings.py        ограничения и доступ студентов
  results*.py             результаты, поиск, выгрузка в Excel
routers/                HTTP-маршруты: auth, tests, quiz, results, review, users (/v2), editor
templates/, static/     страницы и стили
experiments/            эксперимент по выбору модели и порога
scripts/                демо-данные
tests/                  автотесты (pytest)
```

Архитектура трёхслойная: маршруты (`routers`) вызывают сервисы (`services`), сервисы
работают с ядром (`core`) и базой SQLite.

## Тесты

```bat
python -m pip install -r requirements-dev.txt
python -m pytest
```

51 тест: правила оценки, безопасность, прохождение теста и изоляция студентов, ручная
проверка, права доступа, редактор, метрики эксперимента. Тесты работают на временной копии

## Ограничения

- Проверка отрицаний ловит перевёрнутый смысл только через слова «не», «нет», «без» и т. п.
  Перестановку понятий («от цели к фактам» вместо «от фактов к цели») система не замечает —
  для этого нужна модель логического следования (NLI).
- Эксперимент проведён на синтетическом наборе ответов по одной дисциплине; для более
  надёжных выводов нужен набор реальных ответов студентов.
- Незавершённая попытка теста хранится в памяти сервера и теряется при его перезапуске
  (вход в систему при этом сохраняется).
